uxd is now called Testlane. Version 2.0.0 is the first release under the new
name: the package is `@uxfront/testlane`, the command is `testlane`, and every
directory and variable that said uxd now says testlane. Your projects, refs and
workspaces work the same way, so upgrading means swapping the package, moving
two directories and renaming a few variables.

You don't have to do it all at once. Testlane 2.x still reads your old
directories and variables, and warns on stderr until you've moved them, so your
projects keep working while you go through the steps below.

## What changed

| What | uxd 1.x | Testlane 2.x |
|---|---|---|
| Package | `@uxfront/uxd` | `@uxfront/testlane` |
| Command | `uxd` | `testlane` |
| Config dir | `~/.uxd` | `~/.testlane` |
| Config dir variable | `UXD_CONFIG_DIR` | `TESTLANE_CONFIG_DIR` |
| State dir | `${XDG_STATE_HOME:-~/.local/state}/uxd` | `${XDG_STATE_HOME:-~/.local/state}/testlane` |
| Debug output | `UXD_DEBUG=1` | `TESTLANE_DEBUG=1` |
| Variables your commands get | `UXD_PATH`, `UXD_PORT`, … | `TESTLANE_PATH`, `TESTLANE_PORT`, … |
| `root` that `setup` suggests | `~/dev/uxd` | `~/dev/testlane` |
| Repository | `uxfront-com/uxd` | `uxfront-com/testlane` |

Everything else stays as it was. Project files keep their keys and template
variables like `{port}`, and the verbs, flags, `--json` output and
[exit codes](/docs/uxd/cli/exit-codes) are the same.

## Upgrade step by step

### 1. Swap the package

Remove uxd and install Testlane with the package manager you used before:

:::code-group

```bash [npm]
npm uninstall -g @uxfront/uxd
npm i -g @uxfront/testlane
```

```bash [pnpm]
pnpm rm -g @uxfront/uxd
pnpm add -g @uxfront/testlane
```

```bash [yarn]
yarn global remove @uxfront/uxd
yarn global add @uxfront/testlane
```

:::

Then check that it landed:

```bash
testlane version
```

You should see `testlane 2.0.0` or later. The two packages can sit side by side,
since their commands have different names. Keep in mind that uxd 1.x looks in
`~/.uxd`, so it stops finding your projects once you move them in the next step.

### 2. Move your config and state

Move both directories in one go, while no `uxd` or `testlane` command is
running:

```bash
mv ~/.uxd ~/.testlane
mv "${XDG_STATE_HOME:-$HOME/.local/state}/uxd" "${XDG_STATE_HOME:-$HOME/.local/state}/testlane"
```

Move them rather than starting over with `testlane setup`. Once `~/.testlane`
exists, Testlane reads only that and ignores `~/.uxd`. The state directory works
the same way, so a fresh one would leave your existing workspaces out of `list`.

Your repositories and worktrees stay where they are. `defaults.toml` keeps the
`root` you chose, like `"~/dev/uxd"`, so leave it as it is: changing it would
point Testlane at directories where your projects don't live.

### 3. Rename the variables you set or read

Rename `UXD_CONFIG_DIR` to `TESTLANE_CONFIG_DIR`, and `UXD_DEBUG` to
`TESTLANE_DEBUG`, wherever you set them, like your shell profile or a CI job.

Then look for the old names in what Testlane runs for you: your project files,
dev server configs, hooks and scripts. Rename every `$UXD_*` to its `$TESTLANE_*`
twin, like `$UXD_PORT` to `$TESTLANE_PORT`. To find them in your project files:

```bash
grep -rn 'UXD_' ~/.testlane
```

Testlane 2.x still exports every `UXD_*` variable beside its `TESTLANE_*` twin,
with the same value, so a dev server that listens on `$UXD_PORT` keeps working.
It can't tell whether anything reads them, though, so it never warns about
them. That's why it's best to rename them now.

### 4. Update your scripts and aliases

Testlane doesn't install a `uxd` command, so once uxd is gone, a script, shell
alias or CI job that calls `uxd` fails with `command not found`. Replace `uxd`
with `testlane`. The arguments stay the same:

```bash
testlane my-project 42 code
```

### 5. Regenerate shell completions

Your completion script was generated for `uxd`, so it doesn't complete
`testlane`. Generate a new one as in
[Shell completions](/docs/uxd/guides/shell-completions), and remove the old
`eval` line or file. With zsh and a completions directory, that's:

```bash
testlane completions zsh > ~/.zsh/completions/_testlane
rm ~/.zsh/completions/_uxd
```

### 6. Check the result

```bash
testlane doctor
testlane my-project list
```

In the `doctor` output, the config dir ends in `.testlane` and the state dir in
`testlane`, and neither command prints a warning about uxd. `list` shows the
same workspaces as before.

## What 2.x still reads

Testlane 2.x looks for each setting in this order and takes the first one it
finds. The rows marked "warns" are the old names:

| Setting | Order |
|---|---|
| Config dir | `--config-dir` → `$TESTLANE_CONFIG_DIR` → `$UXD_CONFIG_DIR` (warns) → `~/.testlane` if it exists → `~/.uxd` if it exists (warns) → `~/.testlane` |
| State dir | `<state>/testlane` if it exists → `<state>/uxd` if it exists (warns) → `<state>/testlane` |
| Debug output | `TESTLANE_DEBUG=1`, or `UXD_DEBUG=1` (warns) |
| Exported variables | Every `TESTLANE_*` variable, and the same values under `UXD_*` |

`<state>` is `${XDG_STATE_HOME:-~/.local/state}`. Your project's `[env]`, a
command's own `[commands.x.env]` and `--env K=V` still win over both sets of exported
variables, as described in
[Environment and templates](/docs/uxd/configuration/environment-and-templates).

Each warning is one line on stderr, printed at most once per run. It names the
old name, the new one and the fix, like `mv ~/.uxd ~/.testlane`. Warnings never
go to stdout, so `$(testlane …)` and `--json` output stay clean for your
scripts. When the old and the new directory both exist, the new one wins and
nothing warns.

These fallbacks are there to see you through 2.x, so we recommend finishing the
move rather than relying on them.
