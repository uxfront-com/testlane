These verbs take a project **and** a ref:

```
testlane <project> <ref> <verb> [flags] [-- passthrough]
```

## `checkout`

Materializes the workspace and prints its path on stdout. This is the default
verb, and the one to use from scripts.

```bash
testlane my-project feat/login checkout
```

```
→ fetching origin/feat/login
→ worktree ready: ~/dev/testlane/my-project/trees/feat-login
```

| Flag | Effect |
|---|---|
| `--fetch` | Force a re-fetch before materializing |
| `--setup` | Also run `[setup]` (off by default for `checkout`) |
| `--no-setup` | Skip `[setup]` |
| `--json` | Print a result object instead of the path |

```bash
testlane my-project feat/login checkout --json
```

```json
{"project":"my-project","slug":"feat-login","ref":"feat/login","kind":"branch","branch":"feat/login","path":"~/dev/testlane/my-project/trees/feat-login","ports":[3053],"created":true}
```

## `code`

Materializes if needed, then opens the workspace in your editor.

```bash
testlane my-project 42 code
testlane my-project 42 code --editor vim
```

| Flag | Effect |
|---|---|
| `--editor <cmd>` | Override the configured editor for this run |
| `--fetch` | Re-fetch before opening |
| `--setup` / `--no-setup` | Force or skip `[setup]` |

`--json` is not supported for `code`.

## `run <name>`

Materializes, runs `[setup]`, then the named command from `[commands]` inside
the worktree. Passthrough args are appended.

```bash
testlane my-project 42 run dev
testlane my-project 42 run test -- --watch
```

| Flag | Effect |
|---|---|
| `--no-setup` | Skip `[setup]` |
| `--reseed` | Re-copy seed files before running |
| `--fetch` | Re-fetch before running |
| `--port <n>` | Override the allocated port for this invocation |
| `--env K=V` | Add or override one environment variable (repeatable) |

`--dry-run` prints the computed environment as `export` lines followed by the
shell-quoted command, and runs nothing.

## `exec -- <argv…>`

Like `run`, but for an ad-hoc command spawned directly — no shell, so no
quoting surprises.

```bash
testlane my-project 42 exec -- pnpm test
testlane my-project 42 exec --no-setup -- git log --oneline -5
```

Accepts the same environment flags as `run`.

## `shell`

An interactive shell inside the workspace with the full `testlane` environment
exported (`$TESTLANE_PORT`, `$TESTLANE_PATH`, `$TESTLANE_DATA_DIR`, …).

```bash
testlane my-project 42 shell
testlane my-project - shell
```

## `sync`

Re-fetches the ref and hard-resets the worktree to it.

```bash
testlane my-project 42 sync
```

| Flag | Effect on local changes |
|---|---|
| *(none)* | Refuses if the tree is dirty |
| `--stash` | Stash them, then reset |
| `--discard` | Discard them, then reset |
| `--fresh` | Remove the worktree and re-materialize from scratch |

::warning
`--stash`, `--discard` and `--fresh` are mutually exclusive.
::

See [Refresh a workspace](/docs/uxd/guides/refresh-a-workspace).

## `diff`

For a PR workspace with `gh` available, renders `gh pr diff` against the real PR
base. Otherwise falls back to `git diff <merge-base>...HEAD` in the worktree.

```bash
testlane my-project 42 diff
testlane my-project 42 diff --stat
testlane my-project 42 diff --tool
testlane my-project 42 diff -- --color-words
```

| Flag | Effect |
|---|---|
| `--stat` | Summary instead of full patch |
| `--tool` | Use `git difftool` (always local, never `gh`) |

## `info`

One workspace in detail.

```bash
testlane my-project feat/login info
```

```
slug: feat-login
kind: branch
ref: feat/login
branch: feat/login
path: ~/dev/testlane/my-project/trees/feat-login
ports: 3053
status: clean
created: 2026-07-25T05:51:38.363Z
last used: 2026-07-25T05:51:38.827Z
```

| Flag | Effect |
|---|---|
| `--du` | Include on-disk size |
| `--json` | Machine-readable object |

## `rm`

Removes one workspace.

```bash
testlane my-project 42 rm
testlane my-project 42 rm --force --yes
```

| Flag | Effect |
|---|---|
| `--force` | Remove even if the worktree is dirty (discards changes) |
| `--yes` | Skip the confirmation prompt |

To remove several at once, use [`clean`](/docs/uxd/cli/project-verbs#clean).

## `start <name>`

Runs a configured command in the background, so you can hand someone a running
app and get your terminal back. `start` materializes the workspace and runs
`[setup]` and `pre_run` the way `run` does, then starts `commands.<name>` in its
own session and process group, with its output appended to `process.log` in the
workspace's data dir. It returns once `127.0.0.1:{port}` accepts a TCP
connection, prints the URL and leaves the process running after Testlane exits.

```bash
testlane my-project 42 start dev
testlane my-project 42 start dev --json
testlane my-project 42 start dev --timeout 60 --env DEBUG=1
```

```
→ started dev (pid 21819), waiting for 127.0.0.1:6392
→ dev ready on http://127.0.0.1:6392 (pid 21819, log …/.data/pr-42/process.log)
http://127.0.0.1:6392
```

| Flag | Effect |
|---|---|
| `--no-setup` | Skip `[setup]` |
| `--reseed` | Re-copy seed files before starting |
| `--fetch` | Re-fetch before starting |
| `--env K=V` | Add or override one environment variable (repeatable) |
| `--timeout <seconds>` | How long to wait for the port, and for another `start` of the same workspace (default `300`) |
| `--json` | Print one object with `project`, `slug`, `command`, `pid`, `port`, `url`, `log`, `startedAt` and `reused` |

A workspace runs one such process at a time, so `start` is safe to repeat:

- **The same command is running.** `start` prints it with `"reused": true` and
  runs nothing, not even `[setup]` or hooks.
- **Another command is running.** `start` exits `2`, names it and tells you the
  `stop` to run first.
- **Two starts race.** The second waits for the first, for as long as its own
  `--timeout`, then prints the process the first one started.

When the command exits before the port is ready, `start` exits `6` and prints
the last 20 lines of its log. When the port isn't ready within `--timeout`, it
stops the process and exits `6`. The check connects to `127.0.0.1` only, so make
sure your server binds `127.0.0.1:$TESTLANE_PORT` rather than `localhost` or `::1`. If
something else already serves that port, `start` exits `6` before it runs
anything, since it couldn't tell your server's readiness apart.

`--port` is a usage error here: the process always serves the workspace's own
port, so hooks and [`ps`](/docs/uxd/cli/project-verbs#ps) see the same one.
`--dry-run` prints the environment and the command as `run` does, and starts
nothing.

The built-in verb wins over a configured command named `start`, `stop` or
`logs`. Reach that command with `testlane my-project 42 run start`, and `doctor`
warns about the overlap.

## `stop`

Stops the process `start` left running and clears its record. The log stays.

```bash
testlane my-project 42 stop
```

`stop` sends `SIGTERM` to the whole process group, then `SIGKILL` if anything
is left after 10 seconds, so a dev server that `bash -c` started stops too. It
only signals the PID it recorded while that PID still has the start time it had,
so a PID the OS has since given to another process is left alone. With nothing
running, it says so and exits `0`:

```
→ not running: my-project/pr-42
```

`rm` and [`clean`](/docs/uxd/cli/project-verbs#clean) stop a running process
the same way before they remove its workspace, once `pre_clean` has allowed it.

## `logs`

Prints the log of the process `start` ran. With `-f`, it keeps printing new
lines until you press `Ctrl-C`.

```bash
testlane my-project 42 logs
testlane my-project 42 logs -f
```

| Flag | Effect |
|---|---|
| `-f`, `--follow` | Keep printing new lines until interrupted |

The log survives `stop` and a restart, which appends to it, and goes away with
the workspace. With no log yet, `logs` exits `2`:

```
error(E_USAGE): no log for my-project/pr-42
hint: start a command first: testlane my-project <ref> start <name>
```
