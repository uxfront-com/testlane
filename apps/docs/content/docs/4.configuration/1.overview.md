`testlane` reads per-project TOML from one config directory. A repository can
also commit a `.testlane.toml` with its setup, env and commands, which you
approve once and your own file overrides.

## Where the config directory is

```
--config-dir → $TESTLANE_CONFIG_DIR → ~/.testlane
```

The first one set wins. `testlane config path` prints the winner:

```bash
testlane config path
```

```
~/.testlane
```

While you move from the old name, Testlane 2.x also reads the old variable and
directory, with a warning. See
[Upgrading from uxd](/docs/getting-started/upgrading-from-uxd).

## Layout

```
<config-dir>/
  defaults.toml            # optional global defaults
  my-project.toml          # one file per project; filename = project name
  seeds/
    my-project/            # seed file tree for project "my-project"
      .env.local
```

Project names must match `^[a-z0-9][a-z0-9._-]*$`. `defaults` and `seeds` are
reserved.

A repository can add one file of its own, at its root:

```
<repository>/
  .testlane.toml           # optional, read from origin/<default> once you trust it
```

## A repository's `.testlane.toml`

The repo file lets a project's maintainers write its setup, env and commands
once, so you don't have to. It holds only what describes the repository: the
keys about your machine, like `repo_path` or `editor`, stay in your project
file, and the repo file rejects them.

Testlane reads it only from the tip of the default branch, never from the
branch or pull request you check out, and runs its commands only after you
approve that exact content. Where a key is in both files, yours wins.
`testlane config show <project>` prints the merged config and where each key
came from.

[Ship a config with your repo](/docs/guides/ship-a-config-with-your-repo)
walks through it, and
[Commands & hooks](/docs/configuration/commands-and-hooks#from-the-repository)
gives the merge rules.

## `defaults.toml`

Three optional keys, applied to every project that does not override them:

```toml [~/.testlane/defaults.toml]
root = "~/dev/testlane"     # base dir for derived repo_path / worktrees_path
editor = "zed"              # fallback editor preset or template
default_command = "code"    # fallback default verb
```

::warning
`env` and `commands` are **not** allowed in `defaults.toml`, because they
belong to one project: in its project file, or in its repository's
`.testlane.toml`.
::

## Creating and editing

```bash
testlane setup                       # scaffold the config dir and your first project
testlane config add my-project       # create a project file from a starter template
testlane config add https://github.com/my-org/my-project   # add a project from its repository
testlane config edit my-project      # open an existing one
testlane config edit                 # open defaults.toml
```

## Validating

```bash
testlane config validate
```

```
→ all project configs valid
```

Validation is **aggregate** — one run reports every schema error in a file, not
just the first. Pass a project name to check one file. Invalid config exits `3`
(`E_CONFIG`).
