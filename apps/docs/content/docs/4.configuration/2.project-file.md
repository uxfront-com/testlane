One file per project at `<config-dir>/<project>.toml`. The filename is the
project name.

A repository can also commit a `.testlane.toml` that sets some of these keys
for everyone. The tables below mark which keys it may set, and `[env]`,
`[commands.*]` and `[hooks]` are allowed there too. The rest describe your
machine, so they're **user-only** and belong in this file. Your value wins
wherever both files set a key, as
[Ship a config with your repo](/docs/guides/ship-a-config-with-your-repo)
explains.

## A complete example

```toml [~/.testlane/my-project.toml]
repo = "git@github.com:my-org/my-project.git"
default_branch = "main"
editor = "zed"
ports = 2
base_port = 5700

[setup]
run = "pnpm install --frozen-lockfile"
cache_key = ["pnpm-lock.yaml", "**/package.json"]
seed_files = [".env.local"]

[env]
PORT = "{port}"
API_PORT = "{port+1}"

[commands.dev]
run = "pnpm dev"
```

## Repository

| Key | Type | Default | In `.testlane.toml` |
|---|---|---|---|
| `repo` | string | **required** — ssh or https URL | user-only |
| `repo_path` | path | `{root}/{project}/repo` | user-only |
| `worktrees_path` | path | `{root}/{project}/trees` | user-only |
| `default_branch` | string | auto-detected from `origin` HEAD | user-only |

`{root}` comes from `defaults.root`. Path values support a leading `~` only —
no other expansion.

## Behavior

| Key | Type | Default | In `.testlane.toml` |
|---|---|---|---|
| `editor` | string | `defaults.editor` — a preset name or a template | user-only |
| `default_command` | string | `defaults.default_command` — a verb or a configured command name | allowed |
| `ports` | integer 1–10 | `1` — contiguous ports allocated per workspace | allowed |
| `base_port` | integer 1024–65000 | derived per project | user-only |

See [Editors](/docs/configuration/editors) for the preset list, and
[Run dev servers in parallel](/docs/guides/run-dev-servers-in-parallel) for how
`ports` and `base_port` interact.

## `[setup]`

Runs after checkout and before `run`, `exec` or `shell`. Omit the table
entirely and no setup happens.

```toml
[setup]
run = "pnpm install --frozen-lockfile"
cache_key = ["pnpm-lock.yaml", "**/package.json"]
seed_files = [".env.local"]
seed_from = "~/dev/my-project"
```

| Key | Type | Meaning | In `.testlane.toml` |
|---|---|---|---|
| `run` | string | The setup command, templated. Skipped entirely when absent | allowed |
| `cache_key` | string[] | Globs; setup re-runs when their hash changes | allowed |
| `seed_files` | string[] | Relative paths copied into a new worktree | allowed |
| `seed_from` | path | An extra seed source, checked before `seeds/<project>/` | user-only |

::note{title="cache_key is why the second checkout is fast"}
`testlane` hashes the files matched by `cache_key`. If the hash is unchanged since
the last successful setup for that workspace, `run` is skipped. Without a
`cache_key`, setup runs every time.
::

Seeding is covered in [Seed local files](/docs/guides/seed-local-files).

## Strictness

The schema is **strict** — an unknown key is an error, not a warning. That
catches typos like `worktree_path` immediately instead of silently ignoring
them.

```bash
testlane config validate my-project
```

Errors are reported in aggregate, so one run shows you every problem in the
file.

The repo file is strict too. Testlane checks it when it reads it from the
default branch, in `config trust`, `config add` or a command that checks out a
workspace, and names a user-only key and the file to move it to:

```
error(E_CONFIG): my-project:.testlane.toml: editor: user-only key; set it in my-project.toml
```

`config validate` doesn't read the default branch. It checks only the copy of
the repo file you've approved.
